# APP 全流程审查报告

审查时间：2026-07-01  
审查范围：饮食首页、训练页、计划页、更多页、动作库、身体数据、训练偏好、饮食方案。  
证据目录：`C:\Users\Administrator\Documents\健身日历\audit-screenshots\2026-07-01-app-audit`

## 结论

APP 的主线方向已经清楚：饮食记录、训练参考、计划设置、更多设置四个底部入口成立；本地食物识别、菜品图片识别、训练日程联动、动作库也已经有基础能力。

但现在还没有达到“普通用户可长期稳定使用”的完成度。主要问题集中在四类：

1. 页面信息密度和层级仍然不稳定。
2. 训练页在休息日的表达还不够符合健身用户直觉。
3. AI/OCR/体脂估算入口已经有形，但用户对“识别后会发生什么”还不够清楚。
4. 动作库、收藏、今日参考等高级交互依赖长按，发现成本偏高。

## 高优先级问题

### 1. 首页默认内容像测试数据

证据：`01-home.png`

饮食记录输入框下方显示了“一碗面 两棵拳头大的西红柿”。如果这是用户本地缓存，还可以理解；但如果新用户打开也看到类似内容，会被误解为系统默认记录。

建议：
- 新用户空状态应显示示例，不应直接进入“已记录”的视觉状态。
- 示例文案和真实记录要有明显区分。
- 清空状态、今日已记录状态、识别中状态要分开。

### 2. 训练页休息日仍然出现大量训练消耗数据

证据：`02-train.png`

训练计划显示今日休息，但下方仍然出现“训练消耗与赤字”的大数字，容易让用户误解今天仍有训练目标。动作参考已经显示推荐 0 个，这是正确方向，但训练消耗卡片还在强化训练日心智。

建议：
- 休息日时训练页首要内容应变成“恢复日 / 今日不安排训练”。
- 训练消耗卡片可以降级为小卡片，或只显示“基础消耗 / 今日活动消耗”。
- 休息日输入区应引导记录步数、拉伸、恢复状态，而不是默认训练分钟。

### 3. 计划页状态冲突

证据：`03-plan.png`

页面标题是“今日目标与设置”，右上角状态是“未选饮食方案”，下方又有身体数据、训练计划、饮食方案三张入口。它现在更像“设置页”，不像“计划页”。

建议：
- 如果计划页只承担设置入口，标题应改成“目标与方案”或“计划设置”。
- 如果计划页要承担计划概览，应补一张真正的“当前计划摘要”：饮食方案、训练频率、本周安排、目标周期。
- “未选饮食方案”应更突出，因为它会影响训练计划联动。

### 4. 动作库长按功能不可发现

证据：`05-exercise-library.png`

动作库现在支持长按菜单，但普通用户很难知道长按可以收藏、置顶、置底、加入今日参考。顶部说明有“长按”，但卡片本身没有更多按钮或收藏按钮。

建议：
- 卡片右上角加一个小的“...”或星标入口。
- 长按可以保留，但不能作为唯一入口。
- “收藏”类目空状态应提示“长按或点星标收藏动作”。

### 5. 更多页部分功能弱化得像不可用

证据：`04-more.png`

更多页里很多标题和图标颜色很暗，用户可能误以为不可点击。尤其“仪表盘可视化”“外观模式”“字体大小”“高级规则”等都像禁用项。

建议：
- 可点击项和不可点击项要有明确视觉差异。
- 如果“高级规则”当前不可用，应标注“开发中”或隐藏。
- 导出/清除健康数据是高风险操作，清除已有二次确认是好的；导出后应该明确告诉用户导出位置或分享结果。

## 中优先级问题

### 6. 训练偏好页仍然偏“参数设置”，不像普通用户语言

证据：`06-training-preference.png`

训练频率、单次时长、有氧比例是对的，但“参考主流训练拆分”“上下肢拆分”等文案对新手仍偏专业。

建议：
- 增加普通解释：例如“每周 4 天：适合多数健身用户，练 1 天休 1 天或上下肢轮换”。
- 训练偏好保存后，应回到计划页而不是首页，用户更容易确认设置结果。

### 7. 身体数据页承担内容太多

证据：`07-body.png`

身体基线、体重目标、周期、体型、身体成分、OCR、自拍估算都在同一页。优点是集中，缺点是首屏负担变重。

建议：
- 首屏只放必填项和目标。
- 身体成分补充折叠成“高级数据，可选”。
- OCR 和自拍估算入口应解释结果会填入哪些字段。

### 8. 饮食方案页方案文案可读性偏弱

证据：`08-diet-plan.png`

方案卡片文字偏暗，层级不够强。用户选方案时，需要快速判断“我适不适合这个方案”，但当前更像参数列表。

建议：
- 每个方案卡片突出三点：适合谁、执行难度、训练联动方式。
- 生酮/极低碳等高风险方案应增加“不建议多数训练者长期默认使用”的提醒。

## 软件开发视角

1. 目前核心状态都在 Zustand，本地 MVP 合理。但功能越来越多后，store 已经偏大，建议后续拆分为饮食、训练、设置、用户数据四个 slice。
2. 多个页面依赖本地缓存状态，测试数据容易污染体验。建议增加“开发测试数据”和“用户真实数据”的清理开关。
3. 动作库、AI 菜品、OCR、体脂估算都属于异步能力，应统一错误、加载、空状态组件。
4. 长按菜单没有截图级自动交互验证，建议后续补一个组件级测试或 Web 端 Playwright 交互测试。

## UI 设计师视角

1. 深色主题整体统一，但一些文字对比度过低，尤其更多页和计划页部分副标题。
2. 首页饮食卡片目前已经比之前克制，但仍应继续减少重复信息，把“记录输入、识别标签、餐次结果”做成更清晰的流程。
3. 训练页休息日应有独立视觉状态，不应沿用训练日仪表盘。
4. 动作库信息密度高，左侧竖向分类和右侧双列卡片可用，但收藏、置顶、今日参考这些动作需要显性按钮。

## 健身教练视角

1. 训练计划和饮食日联动方向正确，高碳配大肌群、低碳配轻训练是合理方向。
2. 休息日不应给用户压力。建议增加“恢复建议”：睡眠、拉伸、步数、酸痛程度。
3. 训练记录目前只记录文本、分钟和热量，缺少力量训练关键指标：动作、重量、组数、次数、主观强度 RPE。
4. 长期要补“训练进步追踪”：例如卧推重量、深蹲重量、跑步配速、训练总量趋势。

## 健身爱好者视角

1. 饮食记录和 AI 菜品识别是最有吸引力的入口，但需要让用户更快看到“今天吃了什么、还差什么”。
2. 动作库有价值，但收藏和今日参考如果只能长按，用户容易错过。
3. 训练计划如果能显示“本周练几次、哪天休息、为什么今天休息”，信任感会更强。
4. 计划页应该像“我的当前方案”，而不是三个设置入口。

## 建议优先级

1. 重做训练页休息日状态：休息日弱化训练消耗，强化恢复建议。
2. 计划页改成真正的“当前计划总览”：饮食方案 + 训练频率 + 本周安排。
3. 动作库收藏/今日参考做显性按钮，长按只作为快捷方式。
4. 首页饮食记录空状态和真实记录状态分离。
5. 身体数据页做折叠分组，减少首屏负担。
6. 统一异步功能的加载、错误、权限、成功反馈。
