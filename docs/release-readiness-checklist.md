# 发布前全链路检查清单

本清单用于把“能在本机跑”和“可以给真实用户试用”分开。每次打包 APK、开放 AI 图片接口或发测试版本前，都按这里复核。

## 1. 品牌与包名

- [ ] `apps/mobile/app.json` 的 `name` 已改成最终 APP 名称。
- [ ] `slug`、`scheme`、Android `package`、iOS `bundleIdentifier` 与最终品牌策略一致。
- [ ] 百度云应用名称、移动端包名、隐私政策里的 APP 名称一致。
- [ ] 启动图、图标、权限弹窗文案不再出现旧名“健身日历”。

## 2. AI/OCR 图片接口

- [ ] `API_ALLOWED_ORIGINS` 只包含正式前端域名和必要的本地调试地址。
- [ ] `AI_RATE_LIMIT_MAX` 与 `AI_RATE_LIMIT_WINDOW_MS` 已按测试用户规模配置。
- [ ] `AI_IMAGE_MAX_BYTES` 已设置，默认不超过 5MB。
- [ ] 客户端在发送菜品、营养表、体成分报告图片前，会先做格式校验、体积校验，Web 端可自动压缩大图。
- [ ] 百度 AK/SK 只存在服务端环境变量里，不进入 Expo public env。
- [ ] 菜品识别、营养表 OCR、体成分报告 OCR 都能在断网/百度失败时给出可手填的失败态。

## 3. 饮食记录链路

- [ ] 文字输入：餐次、数量、食物、泛化细分、热量估算均正确。
- [ ] 图片菜品识别：识别结果进入对应餐次，并同步保存到我的菜单。
- [ ] 食物详情：用户能修改细分类型和重量，餐次热量实时更新。
- [ ] 删除标签：餐次中的食物标签可删除，删除后总热量和宏量营养同步变化。
- [ ] 我的菜单：营养表 OCR 生成的自定义食物可复用、可删除。

## 4. 身体数据链路

- [ ] 必填项：年龄、体重、身高为空时不能误判 onboarding 完成。
- [ ] 报告 OCR：体脂率、BMI、骨骼肌、身体水分、基础代谢能尽量回填。
- [ ] 自拍/视频估体脂：结果明确显示为估算，支持手动修改。
- [ ] 上传图片默认不长期保存裸图，只保存必要结果和文件名。

## 5. 训练记录链路

- [ ] 今日练布局在小屏下不重叠，昨日/今日/明日三栏可读。
- [ ] 推荐动作 3x3 展示完整，动作库可进入、可返回。
- [ ] 训练记录能解析自然语言、分钟、重量等级，并影响训练消耗。
- [ ] 训练页能解释“消耗热量”和“赤字”与饮食页的关系。

## 6. 导航与页面规则

- [ ] 底部标签一级路由不显示左上返回。
- [ ] 二级/三级页面显示左上返回，并能回到上一级。
- [ ] 首次进入未完成资料时，进入身体数据 onboarding。
- [ ] 清除健康数据后，再次进入仍能回到 onboarding。

## 7. 验证命令

```powershell
pnpm typecheck
pnpm test
pnpm --dir apps/mobile export:web
pnpm audit --audit-level moderate
```

## 8. 真机/浏览器手工检查

- [ ] Android 相册权限、相机权限、视频选择权限都能触发系统弹窗。
- [ ] 断网时本地饮食和训练核心功能仍可用。
- [ ] 低端机连续输入饮食记录不卡顿。
- [ ] Web 预览和 APK 里的中文没有乱码。
- [ ] 隐私政策覆盖菜品照片、体成分报告、自拍/视频的用途。
