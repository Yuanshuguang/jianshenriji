# 食物数据库 · 别名歧义检测报告（2026-07-08）

> 由专家团 `food-db-fix` 任务产出，配合 `scripts/validate-foods.mjs` 规则5生成。
> 完整机器可读列表见该校验脚本输出。

## 一、结论

运行时库中存在 **472 个"别名指向 >1 个不同食物"** 的歧义 alias。多数良性（同物异名、品牌/产地别名），但有一类会**直接导致搜索失效**——多个不同食物共用同一别名，用户搜该词会得到互不相同的多条结果，无法区分。

**严重度**：🟡 P2（搜索精度，非计算正确性）。本轮**不手改生成文件**，原因同同名冲突报告（见第三节）。

## 二、重点案例：三种乳制品都别名"黄油/淡奶油"（原审计点名项，已核实）

`curated-foods.ts` 中存在三条食物，别名数组**完全相同**：
```
["黄油","白脱","乳脂","淡奶油"]
```
分别位于第 **129 / 142 / 4068** 行（大概率为 黄油 / 奶油 / 淡奶油 三种不同乳制品）。后果：
- 搜"黄油" → 同时返回黄油、奶油、淡奶油三条；
- 搜"淡奶油" → 同样返回三条；
- 用户无法区分，且奶油/淡奶油被错误关联"黄油"语义。

**根因**：CSV 导入时别名被批量复制，未做语义去歧义。

## 三、为何不直接手改（关键约束）

`curated-foods.ts` 为**自动生成文件**（头注：`pnpm --dir shared import:curated-foods` 重导入会整体覆盖）。手动编辑其中别名，**下次重导入即丢失**。因此别名歧义收敛必须走管线级方案。

## 四、修复方案（按安全度排序）

### 方案 A（推荐，零风险、不改生成文件）：别名覆盖层
新增 `shared/data/food-alias-overrides.ts`：
```ts
export const aliasOverrides: Record<string, string[]> = {
  // 仅保留各食物正确的别名，剔除错误共享
  "butter-id": ["黄油", "白脱", "乳脂"],
  "cream-id":  ["奶油", "稀奶油"],
  "whipping-cream-id": ["淡奶油", "搅打奶油"],
};
```
在搜索/归一化阶段，用覆盖层**覆盖**生成文件中的别名（而非修改它）。这样：
- 不动 `curated-foods.ts`，重导入不受影响；
- 可渐进式治理 472 个歧义，每条独立评审。

### 方案 B：源头修复
在源 CSV 中修正别名列后重跑导入。适合批量清理，但需重新生成并回归。

### 方案 C：搜索层消歧
搜索时若某 alias 命中多个食物，按来源权重/置信度只呈现标准条目（与同名冲突的方案 C 一致）。

## 五、建议落地节奏

1. **短期**：本报告记录 + 搜索层对"别名命中多食物"做排序收敛（UI 层，零数据风险）。
2. **中期**：实施方案 A，优先治理"黄油/奶油/淡奶油"等高影响歧义。
3. **长期**：结合校验脚本规则5 做 CI 监控。

## 六、需人工 sign-off 项

- 472 个歧义 alias 中，哪些属于"必须去歧义"（影响搜索），哪些属于"良性同物异名"（可保留），需产品/营养确认。
- 方案 A/B/C 选择需架构确认。
