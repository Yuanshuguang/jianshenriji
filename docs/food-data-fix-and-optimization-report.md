## 三、数据源优先级策略

### 3.1 推荐的数据源优先级

```
┌─ 优先级 1：中国食物成分表（CFC）第6版标准版
│   └─ 适用：所有中国常见食物（主食、蔬菜、水果、肉类、水产、蛋奶、豆制品）
│   └─ 特点：基于中国人群饮食习惯，烹饪方式贴合实际
│
├─ 优先级 2：中国食物成分表（CFC）第6版普及版
│   └─ 适用：CFC标准版未收录的食物
│   └─ 特点：数据量更大但部分为估算值
│
├─ 优先级 3：USDA FoodData Central
│   └─ 适用：西式食物、进口食品、CFC未收录的现代加工食品
│   └─ 特点：数据精确度高，但烹饪方式和份量基于美国习惯
│
├─ 优先级 4：日本食品成分表（第七版）
│   └─ 适用：日式料理、寿司、日式调味料
│   └─ 特点：亚洲饮食习惯接近中国，可信度高
│
├─ 优先级 5：GB 28050 预包装食品营养标签
│   └─ 适用：市售包装食品、饮料、零食
│   └─ 特点：厂商自报数据，可能有±20%误差
│
└─ 优先级 6：类比估算 + LLM 辅助
    └─ 适用：网红食品、新式饮品、无数据记录的菜品
    └─ 特点：置信度最低，需人工复核
```

### 3.2 混用数据源的处理原则

**当前问题**：鸡胸肉条目的热量取自CFC(133kcal)但蛋白质取自USDA(24g)，导致数据源混用。

**修复原则**：
1. **同一条目的所有营养素必须来自同一数据源**
2. 如必须混用（如CFC有热量但缺某营养素），需在 `nutritionBasis` 字段标注
3. CFC有数据的食物，不得用USDA数据覆盖
4. CFC无数据的食物（如培根），可在 `reviewNote` 中注明"CFC未收录，采用USDA"

## 五、数据库结构优化建议

### 5.1 🔴 新增「烹饪用油量」字段（优先级：高）

**问题**：中餐炒菜的热量极大程度上取决于烹饪用油量，同一道菜不同餐厅油量可差 2-3 倍。当前数据库无此维度。

**建议**：在 CSV 中新增字段 `cookingOilEstimate`，取值范围：

| 标注 | 用油量 | 适用场景 |
|------|--------|----------|
| 少油 | 5-8g/份 | 家常做法、轻食 |
| 标准 | 10-15g/份 | 普通餐厅 |
| 重油 | 20-30g/份 | 川菜、湘菜、外卖 |
| 油炸 | 30-50g/份 | 油炸菜品(实际吸油率10-15%) |

**影响**：一道「酸辣土豆丝」标准版185kcal，重油版可达 250-280kcal。

### 5.2 🔴 新增「份量标准化参照」表（优先级：高）

**问题**：用户输入"一碗饭"、"一份炒菜"时，份量高度主观。

**建议**：建立中国常见餐具份量标准化参照表：

| 一碗米饭(餐厅) | 250g | 米饭 | ±20g |
| 一份炒菜(标准) | 300g | 各类炒菜 | ±50g |
| 一份炒菜(大份) | 500g | 外卖大份 | ±50g |
| 一盘凉菜 | 200g | 凉拌菜 | ±30g |

### 5.5 🟡 数据治理流程建议（优先级：中）

**问题**：82% 记录来源不可追溯，数据质量缺乏持续维护机制。

**建议**：

1. **建立数据审核流水线**
   - 每月抽取 5% 记录进行人工复核
   - 优先复核「低置信度」和「Atwater偏差」标记的记录
   - 复核结果写入 `reviewStatus` 和 `reviewNote`

2. **建立食物数据贡献机制**
   - 用户可通过 APP 反馈「这道菜热量不对」
   - 反馈数据进入审核队列
   - 审核通过后更新数据库

3. **数据版本管理**
   - CSV 文件增加 `version` 和 `lastUpdated` 字段
   - 每次更新生成 changelog
   - 支持版本回滚

4. **与权威数据源定期同步**
   - 每季度同步 CFC 更新（如有新版）
   - 每半年同步 USDA FoodData Central 更新
   - 同步时进行 Atwater 一致性校验

## 六、蒸蛋变体设计缺陷及建议

### 当前问题

蒸蛋（鸡蛋羹）变体将热量设为 62kcal/100g，但份量单位仍沿用基础鸡蛋的「个」=55g。实际一碗鸡蛋羹重量通常 150-200g（含水蒸制），导致：

- 用户选「蒸蛋，1个」→ 计算 62×55/100 = 34kcal
- 实际一碗蒸蛋 → 应为 62×180/100 = 112kcal
- **偏差 -70%**

### 建议方案

变体系统目前不支持覆盖份量单位。两个可选方案：

**方案 A（推荐）**：将蒸蛋从「egg-cooking」变体族中独立出来，作为独立食物条目
```
food("steamed-egg", "蒸蛋", ["鸡蛋羹", "水蒸蛋", "炖蛋"], "dish", 62, 5.5, 4, 1.2, 180, [["碗", 180], ["份", 180]])
```

**方案 B**：扩展变体系统，支持覆盖 `defaultUnitGram` 和 `servingUnits`
