# APP 数据详情解释任务清单

原则：只在用户主动点击数据时解释。每个详情只回答“为什么是这个数、由哪些来源组成、用户应该如何理解”，不做百科式说明，不展示算法内部日志。

## P0：每日高频数据

- [x] 饮食首页：热量赤字 / 摄入热量详情
  - 入口：饮食首页顶部热量圆环、热量指标行。
  - 回答：今日实际摄入是多少、目标是多少、差额是多少、差额来自哪些食物或餐次。
  - 展示：总览仪表盘 + 来源图谱 + 食物/餐次切换。
  - 验收：用户能一眼看出热量差额，并能看到具体来源。
  - 状态：已接入详情弹窗，已改为仪表盘展示，完成率已改为比例刻度；已修正“还差/超出”语义和无记录空状态。

- [ ] 饮食首页：蛋白质详情
  - 入口：饮食首页蛋白质指标行。
  - 回答：哪些食物提供蛋白、三餐占比、系统为什么推荐这个蛋白目标。
  - 展示：总览仪表盘 + 食物贡献排行 + 餐次占比 + 简短目标原因。
  - 验收：用户能判断蛋白主要来自哪些食物，以及是否集中在某一餐。
  - 状态：已有基础详情入口，待按“不过度解释”原则做文案和图形收口。

- [ ] 饮食首页：脂肪详情
  - 入口：饮食首页脂肪指标行。
  - 回答：脂肪来自哪些食物、是否集中在某一餐、为什么有这个目标范围。
  - 展示：总览仪表盘 + 高脂来源排行 + 餐次占比 + 简短目标原因。
  - 验收：用户能快速发现脂肪超标或偏低的主要来源。
  - 状态：已有基础详情入口，待按“不过度解释”原则做文案和图形收口。

- [ ] 饮食首页：碳水详情
  - 入口：饮食首页碳水指标行。
  - 回答：碳水来自哪些食物、和今天高/中/低碳日是否匹配、为什么目标是这个数。
  - 展示：总览仪表盘 + 碳水来源排行 + 餐次占比 + 日型说明。
  - 验收：用户能理解今天为什么是这个碳水目标。
  - 状态：已有基础详情入口，待按“不过度解释”原则做文案和图形收口。

- [ ] 今日餐次：单餐详情
  - 入口：早餐、午餐、晚餐、加餐卡片。
  - 回答：这一餐推荐/实际吃了什么、占全天多少、和目标差在哪里。
  - 展示：单餐仪表盘 + 推荐/实际对比 + 食物列表 + 宏量占比。
  - 验收：用户点开单餐后能看懂这一餐是否合理。

- [ ] 赎罪页：差额详情
  - 入口：赎罪页今日差额、累计差额、分摊方案。
  - 回答：差额来自饮食还是训练、哪些餐次造成偏差、系统建议如何分摊。
  - 展示：差额来源图谱 + 饮食/训练拆分 + 分摊方案影响。
  - 验收：用户能理解“赎罪”不是惩罚，而是把偏差重新安排回目标轨道。

## P1：周期性理解数据

- [ ] 训练页：训练消耗详情
  - 入口：训练页消耗估算、实际训练记录。
  - 回答：消耗如何估算、来自哪些动作/时长、实际训练和计划差多少。
  - 展示：动作贡献排行 + 时长/强度/体重影响摘要。
  - 验收：用户能理解训练消耗是估算值，并知道主要来自哪些动作。

- [ ] 训练页：今日训练状态详情
  - 入口：训练页今日训练状态。
  - 回答：为什么今天推荐这些训练、和饮食日型如何联动。
  - 展示：训练日型 + 推荐理由 + 饮食计划联动标签。
  - 验收：用户能理解高碳日、低碳日和训练强度之间的关系。

- [ ] 计划页：每日目标热量详情
  - 入口：计划页每日目标热量、当前目标卡。
  - 回答：目标体重、剩余天数、当前体重如何共同决定每日热量。
  - 展示：目标公式摘要 + 输入项列表 + 结果卡。
  - 验收：用户能理解每日热量不是随意给出的。

- [ ] 计划页：目标进度详情
  - 入口：计划页目标进度、剩余天数。
  - 回答：当前进度是否落后、按当前节奏预计何时达成。
  - 展示：进度条 + 当前节奏 + 预计达成时间。
  - 验收：用户能判断是否需要调整目标期限或执行强度。

- [ ] 饮食计划详情：日型目标详情
  - 入口：饮食计划详情里的高碳/中碳/低碳日目标。
  - 回答：不同日型为什么碳水不同、适合什么训练日。
  - 展示：日型对比表 + 训练联动说明。
  - 验收：用户能理解不同日型不是随机变化。

## P2：低频但有解释价值的数据

- [ ] 我的菜单：食物营养来源详情
  - 入口：我的菜单食物条目。
  - 回答：这个食物数据来自内置库、用户自定义、OCR 还是联网补全。
  - 展示：来源类型 + 每 100g 营养 + 是否可编辑。
  - 验收：用户能判断这个食物数据是否可信、是否需要修改。

- [ ] 储备食物：推荐分配详情
  - 入口：储备食物生成推荐饮食后的餐次结果。
  - 回答：为什么这些储备食物被分配到这些餐次。
  - 展示：餐次分配原因 + 宏量闭合程度 + 不足提示。
  - 验收：用户能理解推荐饮食不是随机分配。

- [ ] 动态调整规则详情
  - 入口：我的/设置里的动态调整规则，赎罪页规则入口。
  - 回答：哪些规则开启、哪些差额会触发调整、哪些不会。
  - 展示：规则开关状态 + 触发条件 + 示例。
  - 验收：用户能理解系统什么时候会自动调整计划。

- [ ] 体重目标详情
  - 入口：计划页或我的身体数据。
  - 回答：目标体重、当前体重、目标期限之间的关系。
  - 展示：当前/目标/差距 + 期限压力提示。
  - 验收：用户能判断目标是否现实。

## 暂不做

- [ ] 外观模式、字号、仪表盘样式的数据解释
  - 原因：这是偏好设置，不需要来源解释。

- [ ] 普通按钮入口说明
  - 原因：容易变成 UI 教程，和数据解释目标不一致。

- [ ] AI/OCR 技术过程日志
  - 原因：用户关心结果来源和可信度，不需要看技术细节。

- [ ] 每个食物库字段的完整数据溯源
  - 原因：复杂度高，当前阶段先做到来源类型和可编辑。
