# 健身APP 数据联动失效根因分析

## 问题现象

用户反馈：UI改版前，食物摄入、准备吃什么、实际吃了什么、训练内容、消耗等数据互相联动；改版后各数据成了孤岛，互相不联动。

---

## 根因总结（两个层面）

### 层面一：UI 视觉联动断裂（改版直接导致）

改版时为了"饮食页只放饮食内容"，**删除了饮食页的「今日训练」横条**，导致饮食页和训练页之间失去了唯一的视觉桥梁。

| 联动关系 | 旧版（v1） | 新版（当前） |
|---------|-----------|------------|
| 饮食页展示训练信息 | ✅ 训练横条显示 todayWorkout.title + 动作 + 计划消耗 | ❌ 计算了 todayWorkout 但未展示 |
| "今日消耗"数字来源 | ✅ 横条直接显示 plannedTrainingCalories | ❌ 只剩数字，无来源说明 |
| 三核心指标可见性 | ✅ 摄入/消耗/赤字 三独立大卡(28px) | ⚠️ 合并进仪表盘小字(18px) |
| 训练页展示饮食影响 | ❌ 本来就没有 | ❌ 副标题写"联动饮食"但无实际展示 |

**证据**：
- 旧版 `index.tsx`（file-history `97c1be34f7b40f4d@v1`）第 302-321 行有完整的训练横条
- 工作日志（`0a3135d0ede262f0@v5`）明确记录："移除「今日训练」横条区块，饮食页现在只保留和吃有关的内容"
- 新版 `index.tsx` 第 72-73 行仍计算 `todayWorkout` 和 `plannedTrainingCalories`，但仅用于底层计算，UI 不展示

### 层面二：核心引擎未实现（PRD 规划但未做）

PRD 第 7 节规划的 **Flexible Plan Engine**（动态计划引擎）完全没有实现，`shared/domain/plan-engine/` 是空目录。

| PRD 规划的联动能力 | 实现状态 | 现状 |
|-----------------|---------|------|
| 热量余额（跨天分摊） | ❌ 未实现 | 只有当天 foodDelta + trainingDelta 简单相加 |
| 营养余额（连续多日缺口） | ❌ 未实现 | 只算当天 actualGap，无跨天累计 |
| 训练余额（恢复时间管理） | ❌ 未实现 | getNextWorkoutAfterFeedback 只做简单顺延 |
| 训练日联动饮食宏量调整 | ❌ 未实现 | PRD要求"训练日保留更多碳水"，实际无此逻辑 |
| 训练疲劳联动次日强度 | ❌ 未实现 | fatigue 字段存了但未影响计划生成 |

**证据**：
- `shared/domain/plan-engine/` 目录存在但为空
- `features/adjustments.ts` 的 `buildDailyAdjustmentSummary` 只做单日 delta，无跨天余额
- PRD 第 7.3 节明确要求训练余额"联动饮食热量和碳水"，第 6.2 节要求"训练日保留更多碳水"

---

## 底层联动逻辑现状（未完全断裂）

需要说明：**底层数据计算层面的部分联动仍然存在**，只是 UI 上看不出来：

```
饮食页 index.tsx 第 87-94 行（仍正常工作）：
├─ burnCalories = hasTrainingFeedback 
│   ? actualTraining.calories + tdee - calories  ← 读取训练页数据
│   : tdee
├─ deficit = burnCalories - actualIntakeCalories  ← 饮食+训练联动
└─ adjustment = buildDailyAdjustmentSummary({     ← 动态调整联动
       actualTotals,        ← 饮食数据
       actualTrainingCalories ← 训练数据
   })
```

所以用户在训练页修改训练反馈后，饮食页的"今日消耗""赤字""后续调整"数字**理论上会更新**（Zustand 响应式），但因为：
1. 训练横条被删，用户不知道"今日消耗"和训练有关
2. 三个数字缩成了仪表盘小字，不醒目
3. 没有任何视觉提示说"这个数字来自训练页"

→ 用户**感觉**数据不联动，实际上是**联动了但看不见**。

---

## 修复建议

### 优先级 P0：恢复视觉联动（低成本，立竿见影）

1. **饮食页恢复训练摘要**（不是完整横条，而是轻量提示）：
   - 在仪表盘卡片的"今日消耗"行旁加一个小标签，如"含训练 XXX kcal"
   - 或在仪表盘下方加一行紧凑的训练摘要条（标题+消耗，不含完整动作列表）

2. **训练页增加饮食影响展示**：
   - 在消耗进度卡下方加一个"今日热量赤字"小卡，显示 `deficit` 值
   - 或在训练反馈提交后，显示"本次训练影响：今日赤字 +XX kcal"

3. **三核心指标恢复独立可见性**：
   - 摄入/消耗/赤字 在仪表盘内用更醒目的排版（当前18px太小）

### 优先级 P1：实现核心引擎（高成本，PRD 核心能力）

1. **实现 plan-engine 热量余额**：
   - 记录每日偏差，跨天分摊
   - 替换当前 `buildDailyAdjustmentSummary` 的单日 delta 逻辑

2. **训练日联动饮食宏量**：
   - 训练日：碳水目标上调 10-15%
   - 休息日：碳水目标下调，蛋白保留
   - 在 `recommendMacroAwarePortions` 中注入训练日标志

3. **训练恢复管理**：
   - 记录每次训练的部位和强度
   - 生成下日训练时避开未恢复部位
