> 审计日期: 2026-07-04  
> 审计角色: 食物营养数据分析师  
> 审计范围: 健身日历 APP 全量食物数据（CSV 数据库 + 内置食物目录 + 变体覆盖系统）

### 数据流转架构

```
用户输入食物 → getFoodCatalog() 合并四层数据源（按 id 去重）
  → resolveFoodByVariant() 根据变体标签覆盖营养值
  → calculateFoodTotals() 按 grams/100 等比例换算
```

去重优先级：customFoods > foods(内置) > categoryFallbackFoods > csvGeneratedFoods

## 三、交叉验证发现（按严重度排序）

### 🔴 P0 — 严重错误（影响用户热量计算准确性）

#### P0-1: 内置牛奶热量显著偏低

| 数据源 | 食物名 | 热量(kcal) | 蛋白(g) | 脂肪(g) | 碳水(g) |
|--------|--------|-----------|---------|---------|---------|
| 内置 `index.ts:162` | 牛奶 | **54** | 3.2 | 3.2 | **3.4** |
| 变体 `milk-fat/全脂` | 全脂牛奶 | **61** | 3.2 | 3.4 | **4.8** |
| CSV `EXT0126` | 纯牛奶(代表值,全脂) | **65** | 3.3 | 3.6 | **4.9** |
| 中国食物成分表(6版) | 牛奶(均值) | 54~65 | 3.0~3.5 | 3.2~3.8 | 4.6~5.1 |
| USDA FDC | Whole milk | 61 | 3.24 | 3.25 | 4.52 |

**问题分析**：
- 内置值 54 kcal 处于中国食物成分表范围下限，碳水 3.4g 明显偏低（其他数据源均在 4.5-5.1）
- 用户搜索"牛奶"时获得 54 kcal，但选择"全脂"变体后跳变为 61 kcal（+13%），体验不一致
- **影响**：每天喝 250ml 牛奶的用户，热量偏差约 17.5 kcal/天（54 vs 61 × 2.5），累积到月度约 525 kcal

**修复建议**：将内置牛奶值调整为 61 kcal / P3.2 / F3.4 / C4.8，与变体系统和 CSV 保持一致

---

#### P0-2: 核桃宏量营养素与热量不匹配

| 字段 | 内置值(`index.ts:200`) | 中国食物成分表(6版) | USDA FDC |
|------|----------------------|-------------------|----------|
| 热量 | 646 kcal | 646 kcal | 654 kcal |
| 蛋白 | 15g | 14.9g | 15.2g |
| 脂肪 | **65g** | **58.8g** | 65.2g |
| 碳水 | **14g** | **19.1g** | 13.7g |

**Atwater 验证**：
- 内置值计算: 15×4 + 65×9 + 14×4 = 60 + 585 + 56 = **701 kcal** ≠ 声称的 646 kcal（偏差 +8.5%）
- CFC值计算: 14.9×4 + 58.8×9 + 19.1×4 = 59.6 + 529.2 + 76.4 = **665 kcal** ≈ 646（含纤维修正后吻合）

**问题分析**：内置核桃的脂肪值（65g）过高、碳水值（14g）过低，与声称的热量（646 kcal）不一致。热量值取自中国食物成分表，但宏量营养素拆分有误。

**修复建议**：脂肪修正为 58.8g，碳水修正为 19.1g

#### P0-3: 培根蛋白值严重偏低

| 字段 | 内置值(`index.ts:348`) | USDA FDC (Bacon, pan-fried) |
|------|----------------------|----------------------------|
| 热量 | 541 kcal | 541 kcal ✓ |
| 蛋白 | **12g** | **37g** |
| 脂肪 | 42g | 41.8g ✓ |
| 碳水 | 1g | 1.4g ✓ |

**Atwater 验证**：
- 内置值计算: 12×4 + 42×9 + 1×4 = 48 + 378 + 4 = **430 kcal** ≠ 声称的 541 kcal（偏差 -20.5%）
- USDA值计算: 37×4 + 41.8×9 + 1.4×4 = 148 + 376.2 + 5.6 = **530 kcal** ≈ 541 ✓

**问题分析**：热量值（541 kcal）来自 USDA 煎培根数据，但蛋白值（12g）可能是生培根或不同部位的值，导致 Atwater 计算偏差高达 20.5%。用户记录培根时热量正确但蛋白严重低估。

**修复建议**：蛋白修正为 37g（与 USDA 煎培根一致）

#### P0-4: 鸡胸肉蛋白值偏高且热量不匹配

| 字段 | 内置值(`index.ts:154`) | 中国食物成分表(6版) | USDA FDC |
|------|----------------------|-------------------|----------|
| 热量 | 133 kcal | 133 kcal ✓ | 165 kcal |
| 蛋白 | **24g** | **19.4g** | 31g |
| 脂肪 | 2.5g | 5.0g | 3.6g |
| 碳水 | 0g | 2.5g | 0g |

**Atwater 验证**：
- 内置值计算: 24×4 + 2.5×9 + 0×4 = 96 + 22.5 + 0 = **118.5 kcal** ≠ 声称的 133 kcal（偏差 -10.9%）

**问题分析**：热量值（133 kcal）取自中国食物成分表，但蛋白值（24g）高于 CFC 的 19.4g，更接近 USDA 熟鸡胸肉的值。热量和宏量营养素来自不同数据源，未做一致性校验。

**修复建议**：统一数据源。若按 CFC：P19.4/F5.0/C2.5=133kcal ✓；若按 USDA 生鸡胸：P31/F3.6/C0=165kcal。建议采用 CFC 值保持与中国食物成分表一致性。

#### P1-4: CSV 同名冲突记录数量庞大

共 **318 条**记录标记为"同名冲突待核验"，占总量 12.6%。典型案例如下：

| foodCode | foodName | 热量(kcal) | 冲突条目 | 热量差 |
|----------|----------|-----------|----------|--------|
| EXT0010 | 奶油 | 879 | EXT0017 奶油 785 | 94 kcal (10.7%) |
| EXT0016 | 酥油 | 860 | EXT0018 酥油 718 | 142 kcal (16.5%) |
| EXT0293~0297 | 栗子[板栗] | 186/192/168/182/183 | 5条同名 | 最大差 24 kcal (14.3%) |
| EXT0370 | 腐竹 | 461 | EXT0391 腐竹 485 | 24 kcal (5.2%) |
| EXT0503 | 葡萄柚 | 33 | EXT0504 葡萄柚 40 | 7 kcal (21.2%) |

**问题分析**：
- 奶油 EXT0010（879kcal, F97.0）和 EXT0017（785kcal, F86.0）可能分别对应"黄油/无水奶油"和"稀奶油"，但 alias 完全相同，搜索时无法区分
- 栗子 5 条同名记录热量从 168 到 192，用户无法判断应该使用哪条
- 这些冲突记录的 `isActive` 均为"否"（被标记为不活跃），但数据仍在 CSV 中保留

#### P1-5: 变体覆盖逻辑可能产生意外营养跳变

变体系统通过 `resolveFoodByVariant()` 完全覆盖基础食物的营养值。当用户选择变体时，所有四个营养字段被替换，而非按比例调整。

**典型案例**：
- 基础食物 `豆腐`（82kcal）→ 变体 `嫩豆腐`（50kcal），热量下降 39%
- 基础食物 `鸡蛋`（144kcal）→ 变体 `蒸蛋`（62kcal），热量下降 57%
- 蒸蛋的 62kcal 是因为含水量高（鸡蛋羹），单位重量热量确实低，但用户按"个"输入时会困惑

**蒸蛋问题详解**：
- 变体 `蒸蛋` 62kcal/100g，一个蒸蛋碗约 200g = 124kcal
- 基础 `鸡蛋` 144kcal/100g，一个鸡蛋约 55g = 79kcal
- 用户输入"一个蒸蛋"如果按鸡蛋的 55g 计算 → 34kcal，远低于实际 124kcal
- **根本原因**：蒸蛋含大量水，重量远大于原始鸡蛋，但 APP 未提供含水量换算

### 🟢 P2 — 轻微问题（不影响计算但影响数据治理）

#### P2-1: CSV 82.3% 记录来源无法追溯

2068/2513 条记录标注为"原始数据库（来源待追溯）"，无法确认数据来自中国食物成分表、USDA 还是其他来源。这导致：
- 无法验证数据准确性
- 无法追溯数据更新时间
- 无法在数据源更新时同步刷新

#### P2-2: CSV 置信度分布严重偏低

仅 24 条（1.0%）标记为"高"置信度，552 条（22.0%）为"低"。低置信度记录仍在 `isActive=是` 状态，会出现在搜索结果中。

#### P2-3: 零热量但营养素非零的异常记录

共 16 条记录存在"零热量但营养素非零"问题。典型案例：

| foodCode | foodName | 热量 | 蛋白 | 脂肪 | 碳水 |
|----------|----------|------|------|------|------|
| EXT0254 | 蜂胶液 | 0 | 0.2 | 0 | 0 |
| EXT0258 | 蜂王浆 | 0 | 14.6 | 0 | 0 |
| EXT0424 | 麻子籽 | 0 | 0 | 0 | 0 |

蜂王浆蛋白 14.6g 但热量 0kcal 明显错误（按 Atwater 应至少 58.4kcal）。这些记录的 `isActive` 已设为"否"，不会出现在搜索中，但数据质量仍需修正。

#### P2-4: CSV 别名共享导致搜索歧义

多条不同食物共享同一别名集合，例如：
- EXT0010~EXT0012 三条"奶油"记录都使用相同 alias "黄油，白脱，乳脂，淡奶油"
- 但三条热量差异巨大（879/447/504 kcal）
- 搜索"奶油"时三条都会返回，用户无法区分

## 五、变体系统逻辑审查

### 5.1 变体覆盖机制

```typescript
// resolveFoodByVariant() 核心逻辑
if (!variantLabel || variantLabel === defaultDishVariant) return food;
const option = familyOptions.find(item => item.label === variantLabel);
if (!option?.profile) return food;
return { ...food, ...option.profile };  // 完全覆盖四个营养字段
```

**评价**：覆盖机制简单直接，但存在以下风险：
1. **无区间约束**：覆盖后不校验新值是否在合理范围内
2. **无 Atwater 验证**：覆盖后的营养值可能不再满足 Atwater 公式
3. **无 fallback**：如果用户选择的变体无 profile（如 `raw-protein-cooking` 的"水煮"选项），则返回原食物，但用户可能以为已调整

### 5.2 变体数据准确性抽查

| 变体族 | 变体 | 热量 | 中国食物成分表对照 | 判定 |
|--------|------|------|-------------------|------|

| egg-cooking | 煎蛋 | 199 | 196 | ✅ |

| tofu-product | 嫩豆腐 | 50 | 50 | ✅ |

**问题**：老豆腐变体 82kcal 与中国食物成分表北豆腐 98kcal 偏差 16%，可能是使用了旧版数据。
