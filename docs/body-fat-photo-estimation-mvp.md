# 自拍估体脂最小可落地方案

## 目标

这个功能只做健身 APP 场景下的粗略参考，不做医学级检测。输出结果要能被用户手动修改，并且在 UI 上保持“估算”定位。

## 输入

1. 正面上半身照片或短视频：光线稳定、身体正对镜头、腰腹尽量可见。
2. 可选侧面照片或短视频：用于改善腰腹厚度判断，第一版可以不强制。
3. 用户基础数据：性别、年龄、身高、体重。
4. 可选人工校准值：如果用户有体脂秤或体成分报告数据，用它覆盖或校准照片估算。

## 推理流程

第一版保持轻量，不训练自有模型：

1. 图片/视频采集：使用现有 `expo-image-picker` 选择或拍摄。
2. 本地预处理：限制图片尺寸和大小，只上传压缩后的图片。
3. 基础估算：先用 BMI、性别、年龄计算一个基准体脂率。
4. 视觉修正：根据用户从图片/视频里确认的腹部轮廓、腰腹软硬、肌肉线条可见程度，按性别给基准值加减一个小范围修正。
5. 画面质量修正：用户确认“正面清晰、腰腹可见、光线正常、衣物贴身”等条件，条件越完整，输出区间越窄；条件不足时只给宽区间。
6. 输出区间：结果用 `约 18%` 或 `16% - 20%`，不要表现成精确检测。

后续增强可以接专门视觉模型：

1. 人体分割或关键点：提取肩宽、腰宽、躯干比例；视频可先抽取 1-3 帧再复用图片模型。
2. 轻量回归模型：输入基础数据 + 视觉比例，输出体脂率区间。
3. 数据回流：用户手动修正后的体脂值，作为本地校准，不默认上传训练。

## 输出

写入 `profile.bodyComposition`：

1. `bodyFatPercent`：估算体脂率。
2. `source = "selfie"`：标记来源为自拍估算。
3. `bodyFatEstimateMin / bodyFatEstimateMax`：估算区间。
4. `bodyFatEstimateReason`：基础数据、画面特征和质量条件的简短依据。
5. 保留 `evidenceName` 和 `evidenceMediaType`，图片本体默认不长期保存。

UI 展示：

1. 主字段仍是体脂率输入框。
2. 识别完成后自动填入，用户可直接修改。
3. 文案使用“自拍估算：约 xx%”，不展示复杂置信度。

## 校准

1. 用户上传体成分报告时，报告 OCR 结果优先。
2. 用户手动修改自拍估算值后，下一次同类估算可以用差值做个人校准。
3. 校准只在本机保存，不作为通用模型结论。

## 隐私

1. 自拍图默认只用于当前识别，不写入长期历史。
2. 上传云端前压缩图片，减少不必要细节。
3. 不保存裸露照片到“历史日志”。
4. 后续如果接第三方模型，必须单独在隐私说明里写明图片用途。

## 真机测试流程

1. Android 权限：首次点击拍照/相册时能弹出权限请求。
2. 相册上传：选择体成分报告后，体脂率、骨骼肌、水分、基础代谢能尽量回填。
3. 拍照上传：拍摄报告图后，也能走同一条 OCR。
4. 自拍估算：选择或拍摄自拍后，体脂率能自动给出粗略结果。
5. 手动修正：用户改体脂率后保存，重新进入页面仍保留。
6. 失败态：断网、百度 OCR 失败、权限拒绝时不崩溃，并允许手填。

## 下一步实现拆分

1. 已完成“拍照/相册/视频”入口和本地估算链路。
2. 已完成 `基础估算 + 性别差异视觉修正 + 画面质量区间修正`。
3. 后续如果要更像真正 AI 视觉识别，需要接入人体分割、关键点或专门体脂估算模型。
4. 完成 Android APK 真机测试后，再决定是否接第三方视觉模型。
