## UX 微交互实现：Reanimated 原生动画（第四轮）

### 决策背景
- 调研发现 **Moti 与 Reanimated v4 不兼容**（GitHub Issue #391），社区正在迁移远离 Moti
- 项目已有 Reanimated v4.4.1（通过 expo-router peer dependency），决定直接使用 Reanimated 原生能力
- 零额外动画库依赖，4 类交互全部基于 Reanimated 实现

### 前置条件修复
1. **react-native-reanimated 加入直接依赖** — 从 expo-router 间接依赖改为 package.json 直接依赖
2. **app.json plugins 添加 reanimated** — 启用 Reanimated config plugin
3. **Android newArchEnabled: false → true** — Reanimated v4 必须使用新架构（Fabric），旧架构不支持
4. **_layout.tsx 添加 import "react-native-reanimated"** — v4 首行初始化要求
5. **AppIcon 新增 loader + check** — Lucide 图标映射扩展，为 LoadingToSuccess 提供图标

### P0: 按钮回弹（Button.tsx 重写）
- 原版用 `<Pressable>` + `state.pressed && { opacity: 0.84 }`
- 改为 `<Animated.View>` + `<Pressable>` 双层包裹
- `useSharedValue(1)` + `withSpring(0.94, {damping:12, stiffness:150})` → 回弹参数
- 所有 Button 组件自动继承回弹效果，`animated` prop 可关闭

### P0: 列表依次入场（StaggerView 组件）
- 新建 `components/shared/StaggerView.tsx`
- 基于 `entering={FadeInDown.delay(i*80).springify()}` + `exiting={FadeOutDown}`
- 食谱：damping=18, stiffness=120（更柔和的入场曲线）
- 饮食页 mealRows.map → StaggerView 包裹 MealRecordCard
- 训练页 customTrainingExercises + suggestedLibraryExercises → StaggerView 包裹

### P1: 加载→成功对勾（LoadingToSuccess 组件）

## LoadingToSuccess 业务场景集成（第五轮）

### 设计师决策
- APP 有 3 类异步操作是用户等待体验最差的：AI菜品识别、AI营养成分表识别、联网食物搜索
- 现有 AsyncStatusBanner 仅文字状态条，无动画反馈，用户感受不到"正在处理"

### 集成方案

1. **AsyncStatusBanner 升级为动画版** — loading 状态嵌入 AppIcon loader + entering={FadeIn}，success 状态嵌入 AppIcon check + entering={ZoomIn.springify().damping(10)}
2. **LoadingState 升级** — 静态圆形 spinner → AppIcon loader + FadeIn 入场
3. **AI 菜品识别按钮** — dishRecognitionBusy 时替换按钮为 LoadingToSuccess loading spinner，空闲时恢复为 Button "AI 识别菜品"
4. **AI 营养成分表按钮** — nutritionOcrBusy 时替换按钮为 LoadingToSuccess loading spinner，空闲时恢复为 Button "识别营养成分表"
5. **联网食物搜索** — PillButton "搜索中..." → LoadingToSuccess loading spinner，搜索完成后显示 ZoomIn spring 对勾 + 文字提示

### 修改文件
