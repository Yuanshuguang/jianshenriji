# PROJECT - 健身日历

> 这个文件回答：这个项目是什么、解决什么问题、明确不做什么。

## 一句话定义

一个离线优先的健身日历应用，把饮食方案、训练计划、今日餐次、记录和动态调整连成闭环，让用户能持续执行而不是只看数据。

## 解决的问题

把原本分散的饮食、训练、记录、识别和调整能力放到同一套可执行流程里，减少“计划有了，但每天不知道怎么吃、怎么练、怎么调整”的断裂感。

## 我们明确不做什么

- 不做纯资讯或社区型健身产品：核心是执行闭环，不是内容分发。
- 不做云端优先的重服务架构：当前目标是本地可运行、低依赖、可离线使用。
- 不做医疗诊断或治疗建议：这里只提供健身与饮食计划辅助，不替代专业医疗意见。
- 不做把所有能力都塞进一个页面的重界面：信息层级要压缩，但不能牺牲可执行性。

## 目标用户

主要给自己管理饮食和训练的人使用，尤其是需要计划、记录、动态调整的人。
不优先面向只想看教程、打卡社交、或者依赖外部教练全程代操作的用户。

## 项目起点与核心信念

这个项目从“饮食计划和训练计划必须联动”开始，核心信念是：
1. 数据要闭合，目标要能落到每天。
2. 页面可以简洁，但规则不能含糊。
3. 计划、实际、调整要在同一条链路里完成。
4. 先保证本地可用，再考虑扩展能力。
